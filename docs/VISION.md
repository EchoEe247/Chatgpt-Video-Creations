# Vision

## Mission

The purpose of this repository is to give me one reusable ChatGPT-driven video production system that can support both real business distribution and original entertainment work without mixing those goals together.

I want proven production capability to stay reusable. If a workflow, rendering method, QA rule, or scene architecture has already been tested and accepted, future sessions should start from that knowledge instead of rebuilding the same proof again.

## Lane A — Business / OSS release marketing

For business work, I do not want generic promotional output that could describe almost any software project. The marketing should be tied to a useful public project and to the exact release being shown.

A viewer should be able to understand:

- what project or tool the video is about;
- which version the video describes;
- what that release actually does;
- what materially changed from the prior canonical release when relevant;
- who the project is useful for;
- where the user can get or use it.

The release version is part of the marketing identity. It should not be hidden as internal metadata while the public video makes release-specific claims.

The broader goal is organized release marketing: when a useful public project ships something worth showing, the marketing system should be able to explain that release clearly, preserve the old release history, and create new material when the project moves forward.

## Lane B — Original animated productions

For original animation, the goal is bigger than producing isolated scenes. I want the system to be capable of developing original shows with seasons, episodes, recurring characters, continuity, and a visual identity that can be reused and improved over time.

That means a show is treated as an actual IP and production system. I do not want Episode 1 to be generated in isolation and then have later episodes forced around whatever happened in that first render.

The season should have a direction before episode implementation starts. Canon should persist. Character and world rules should carry forward. Accepted episodes should become authoritative production history rather than disposable chat context.

## Shared production values

Across both lanes, the same practical rules apply:

- the final video matters more than technical novelty;
- reusable production packages are better than throwaway scripts when the work will continue;
- the actual rendered MP4 must be reviewed instead of assuming successful code means successful video;
- continuity and shared scene geometry matter more than approximate placement;
- release truth and accepted canon outrank stale chat memory;
- research can inform the work, but original productions should be original rather than disguised copies;
- use legitimately reusable free assets/resources when they save time or materially improve quality; adapt them to the production instead of rebuilding everything by default;
- external online video generators do not replace the repository's own production workflow;
- when a technique is weak, learn established practitioner methods before spending long cycles on blind experimentation;
- complexity should be added when it improves the visible result, not just because more complexity is possible.

The main direction is simple: keep what has already been proven, improve what users can actually see or use, and make every serious production easier to continue than the one before it.
