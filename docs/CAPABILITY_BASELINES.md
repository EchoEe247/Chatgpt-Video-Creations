# Capability Baselines

This document defines the current production baseline for the three supported video lanes. It exists so a fresh ChatGPT or agent session can interpret a short request such as "make a business video," "make a 2D animation," or "make a 3D animation" consistently.

These baselines describe the **minimum expected quality/style starting point**, not a permanent maximum. Real projects should improve beyond them when the content warrants it.

---

## 1. Professional / business programmatic video

### What this means

A clean, polished motion-graphics video built programmatically for practical use cases such as:

- product ads;
- TikTok / Reels / Shorts promos;
- software or dashboard explainers;
- service advertisements;
- business metrics and data stories;
- feature launches;
- social content;
- animated titles and calls to action;
- screen-demo-style sequences assembled from supplied assets.

### Current reference baseline

Originating reference artifact: `programmatic_video_demo.mp4`.

Reference characteristics:

- vertical 720×1280;
- 24 FPS;
- H.264 / yuv420p;
- roughly 10 seconds;
- animated typography;
- motion graphics;
- dashboard/UI cards;
- animated numerical chart;
- transitions and easing;
- animated progress/state elements;
- background glow/effects;
- rendered directly to MP4;
- no stock footage or external visual assets required for the demonstration.

### Quality target

This lane should look **professional, intentional, readable, and useful for actual business content**. It should not look like a developer debug visualization.

The user explicitly liked this lane and considers it suitable as a base for real professional work.

### Strengths

This is currently the most practical and reliable lane. It is especially strong when the video can be driven by:

- text;
- numerical data;
- charts;
- screenshots;
- product imagery;
- icons;
- simple illustrations;
- branded color/typography systems;
- UI mockups;
- timed captions;
- transitions;
- music/voiceover supplied or generated by an available tool.

### Expected improvements for real work

For a production video, do not merely reproduce the technical demo. Improve as needed with:

- exact brand styling;
- stronger hook and CTA;
- real product screenshots or footage;
- better typography hierarchy;
- voiceover;
- sound design/music;
- purposeful scene timing;
- platform-specific aspect ratio;
- multiple hook variants for testing.

## 2. 2D animation video

### Default interpretation

When the user asks for a **2D animation video**, start from the **recent rigged 2D baseline**, not the early prototype where static PNGs were moved over a background.

Originating reference artifact: `original_scifi_cartoon_scene_v2.mp4`.

### Current reference baseline

Reference characteristics:

- 1280×720;
- 24 FPS;
- H.264 video + AAC audio;
- roughly 15 seconds;
- original cartoon characters;
- characters built from independently animated parts rather than a single static cutout;
- independent head movement;
- eyes/pupils and gaze direction;
- blinking;
- multiple mouth states;
- articulated arm gestures;
- body/recoil acting;
- animated portal/vortex effects;
- creature entrance/interactions;
- multiple camera shots and close-ups;
- subtitles;
- timed dialogue and basic synthesized voices;
- simple sound effects/ambience.

### Style expectation

The useful target is **limited 2D television/cartoon animation**: clear poses, readable acting, expressive timing, dialogue, cuts, and effects.

The user originally referenced the energy of an adult sci-fi comedy cartoon. Future work may use that general genre/tone as inspiration, but reusable production work should keep **original character designs, names, voices, props, dialogue, and visual identity** rather than copying protected characters or a specific show's exact style.

### What counts as successful 2D animation

A scene should not rely solely on:

- a static character PNG drifting across the screen;
- one unchanged pose for an entire conversation;
- zooming into the same still image to simulate shots;
- mouth graphics detached from the face;
- static portals or effects with only a glow overlay.

Instead, a proper 2D scene should use meaningful changes such as:

- pose changes;
- eye tracking;
- head turns;
- arm/hand gestures;
- body anticipation/recoil;
- expression changes;
- mouth shapes tied to speech;
- independent effects animation;
- shot composition changes;
- reaction timing.

### Current limits

The present lightweight programmatic approach is suitable for stylized limited animation, but it is not equivalent to a full traditional animation studio pipeline.

Harder areas include:

- highly fluid frame-by-frame character animation;
- complex deformable character rigs;
- sophisticated lip sync without stronger speech/phoneme tooling;
- painterly frame-by-frame effects;
- long episodes with high pose diversity unless assets/rigging are expanded;
- premium professional voice acting without an appropriate voice-generation source.

### Preferred animation lane

Between the current 2D and 3D approaches, **2D is presently the stronger animation lane for quality per unit of effort**. Use it by default when the user wants an animated narrative but does not specifically require 3D.

## 3. 3D animation video

### Default interpretation

When the user asks for a **3D animation video**, use the recent V2 baseline: real 3D geometry, real perspective, articulated characters, lighting, camera motion, effects, and audio.

Do **not** use the primitive first 3D prototype as the target quality.

Originating reference artifact: `programmatic_3d_scifi_scene_v2.mp4`.

### Current reference baseline

Reference characteristics:

- 960×540;
- 24 FPS;
- H.264 video + AAC audio;
- roughly 14 seconds;
- actual 3D geometry rendered with a 3D engine;
- perspective projection and real camera parallax;
- cel/stylized character rendering;
- modeled 3D environment and props;
- articulated character arms/legs/hands/head/eyes/mouths;
- multiple camera shots;
- character recoil/weight shift;
- animated portal geometry/energy rings;
- dynamic green portal light contribution;
- creature emergence in 3D space;
- contact-shadow treatment;
- subtitles;
- synchronized dialogue windows;
- voices and simple generated SFX/ambience.

### Visual target

The current realistic target is a **stylized low-poly / cel-shaded indie cartoon or game-cinematic scene**.

It should clearly look and behave like 3D: perspective changes, depth, camera movement, parallax, geometric lighting, spatial interaction, and characters occupying the scene rather than flat sprites pasted onto it.

### Current limits

This lane is more constrained than 2D in the lightweight environment.

Without a full Blender/Maya-class character-production pipeline, difficult areas include:

- advanced skeletal deformation and skinning;
- high-quality facial blendshapes;
- sophisticated walk/run cycles;
- detailed hands and facial anatomy;
- cloth/hair physics;
- complex material systems;
- cinematic global illumination;
- production-grade shadows and reflections;
- high-poly or realistic characters;
- premium motion-capture-style acting;
- Pixar/DreamWorks-level character animation.

### Quality ceiling to communicate truthfully

Current capability can produce a **real stylized 3D animation scene** and can continue improving scene design, geometry, rigs, lighting, camera work, effects, pacing, and sound.

It should not be represented as equivalent to a high-budget feature-animation studio pipeline.

## 4. Choosing the lane

Use this decision rule unless the user explicitly specifies otherwise:

1. **Business/ad/explainer/product/social content** → professional programmatic video.
2. **Narrative/cartoon/character animation** → 2D animation by default.
3. **User explicitly requests 3D, depth, game-cinematic, low-poly, cel-shaded 3D, or modeled scene** → 3D animation.

If a request mixes lanes, combine them intentionally. Examples:

- 2D cartoon character + business product demo;
- 3D product reveal + programmatic titles/data;
- business ad with an animated 2D narrative hook;
- 3D environment with 2D HUD/caption overlays.

---

## 5. Improvement policy

The baseline is a floor, not a rigid template.

For every real production, ask internally:

- Can the character acting be stronger?
- Can the scene composition be clearer?
- Can the audio be better timed?
- Can the first 1–2 seconds hook harder?
- Can the render be more platform-appropriate?
- Can the scene use real product/brand assets?
- Can lighting/effects improve readability?
- Can the video be shortened without losing the message?
- Should multiple variants be rendered?

Improvements are expected when they provide visible value. Avoid complexity that does not improve the finished video.
