# Phase 6 — Creative QA and final assistant-review gate receipt

Date: 2026-09-27

## Goal

Catch visually weak or under-reviewed candidates before user handoff, while keeping aesthetic judgment with the reviewing agent rather than pretending automated metrics are quality scores.

## Implemented

### Creative-QA analyzer

Added:

- `src/core/creative_qa.py`
- `scripts/creativeqactl.py`
- `templates/layout-qa.json`
- `docs/CREATIVE_QA_WORKFLOW.md`

The analyzer produces candidate-bound evidence for:

- FFmpeg freeze detection;
- low-resolution frame-to-frame motion density;
- per-shot motion density mapped through the execution plan;
- camera-family repetition;
- optional safe-area/text-size checks from durable layout metadata;
- 360px-wide phone-scale review frames;
- normal-speed H.264/AAC review clips;
- whole-video contact sheet;
- assistant creative-review template.

Automated signals are explicitly triage evidence. They do not certify composition, acting, story clarity, camera quality, or readability without appropriate evidence.

### Evidence integrity

The creative-QA report hashes:

- the exact candidate;
- its contact sheet;
- every phone-scale frame;
- every normal-speed review clip.

`creativeqactl validate-bundle` verifies those files still exist under the QA directory and still match their recorded SHA-256 values.

The assistant review is separately bound to:

- candidate SHA-256;
- creative-QA report SHA-256.

Each required criterion must include:

- explicit boolean judgment;
- written notes;
- evidence references generated by the same creative-QA bundle.

Failed criteria or recorded defects require a concrete next change.

### Production-controller enforcement

The v2 production runtime now has `workflow.creative_qa_required`.

Backward compatibility:
- older v2 manifests default this field to `false`;
- their historical acceptance state is not rewritten.

New `templates/production-v2.json` manifests set it to `true`.

When enabled:
- `next_action` becomes `creative_qa` after deterministic review evidence exists;
- `assistant-pass` requires `--creative-qa` and `--creative-review`;
- the controller verifies candidate binding, evidence-file hashes, report binding, explicit review judgments, and a PASS result;
- `ready_for_user_review` requires both creative artifacts;
- later user acceptance re-verifies the same bundle, so post-review tampering fails closed.

Candidate resets/repair cycles clear stale creative-QA/review paths.

## Failure behavior proven

Integration tests prove that a new production with `creative_qa_required=true`:

- rejects assistant PASS when creative paths are omitted;
- accepts assistant PASS only with a valid candidate-bound creative report/review;
- refuses later user acceptance if a hashed creative evidence file is modified after review.

## Boundary

Phase 6 improves evidence quality and makes creative review an enforceable gate for new v2 productions.

It does not make automated visual metrics a substitute for a capable model or human watching the actual video. The workflow is stronger precisely because it distinguishes machine-detectable defects from judgment that still requires normal-speed inspection.
